# 소비자분쟁해결기준 PDF 구조적 파싱 가이드

## 1. 개요

### 1.1 대상 문서
- **문서명**: 소비자분쟁해결기준 별표2 (품목별 해결기준)
- **페이지 수**: 134페이지
- **원본 형식**: HWP → PDF 변환
- **특징**: 복잡한 표 구조, 셀 병합, 계층적 데이터

### 1.2 목표
PDF의 표를 **구조화된 JSON**으로 파싱하여 RAG 시스템에 활용

---

## 2. 문서 구조 분석

### 2.1 계층 구조
```
대분류 (Ⅰ. 상품, Ⅱ. 용역)
  └─ 중분류 (1. 농ㆍ수ㆍ축산물, 2. 식품류...)
       └─ 업종 (①란류, ②육류, ③종묘 등...)
            └─ 표 (분쟁유형 | 해결기준 | 비고)
```

### 2.2 표 구조
```
┌─────────────────────┬──────────────────────┬─────────────────────┐
│     분쟁유형         │      해결기준         │        비고          │
├─────────────────────┼──────────────────────┼─────────────────────┤
│ 1) 최상위 분쟁유형   │ o 해결기준           │  * 비고1            │
│   - 2단계 조건       │ o 해결기준           │  * 비고2            │
│   - 2단계 조건       │                      │  * 비고3 (병합셀)   │
│     ㆍ 3단계 조건    │ o 해결기준           │                     │
│     ㆍ 3단계 조건    │ o 해결기준           │                     │
└─────────────────────┴──────────────────────┴─────────────────────┘
```

### 2.3 핵심 문제: 비고 컬럼의 셀 병합
비고 컬럼은 여러 행에 걸쳐 병합되어 있어 단순 위치 기반 매핑 불가

---

## 3. 파싱 규칙

### 3.1 분쟁유형 계층 인식
```
숫자)  → Level 1 (최상위 분쟁유형)
-      → Level 2 (조건)
ㆍ · • → Level 3 (하위 조건)
① ② ③ → 번호가 있는 하위 조건
```

### 3.2 분쟁유형-해결기준 매핑
- **위치 기반**: 같은 행에 있는 것끼리 매핑
- 해결기준은 `o ` 로 시작
- 하위 조건들이 같은 해결기준을 공유할 수 있음

### 3.3 비고 매핑 (핵심!)

```
┌─────────────────────────────────────────────────────────────────┐
│                    비고 매핑 우선순위                            │
├─────────────────────────────────────────────────────────────────┤
│  1순위: 키워드 매칭                                              │
│    - 비고에 특정 키워드가 있으면, 해당 키워드가 등장하는         │
│      분쟁유형/해결기준에 매핑                                    │
│    - 같은 키워드가 여러 곳에 있으면 모두에 매핑                  │
│                                                                 │
│  2순위: 위치 기반 폴백                                           │
│    - 키워드 매칭 실패 시, 같은 행에 있는 항목에 매핑             │
└─────────────────────────────────────────────────────────────────┘
```

**예시**:
```
* "발아 불량은..." → "발아불량"이 포함된 2)에 매핑 (키워드)
* "직접경비: 인건비..." → "직접경비"가 포함된 해결기준에 매핑 (키워드)
* "예상수익은..." → "예상수익"이 등장하는 모든 곳에 매핑 (키워드, 다중)
* "실제 생육상태와..." → 매칭 키워드 없음 → 같은 행 기준 매핑 (위치 폴백)
```

## 5. RAG용 청크 변환

### 5.1 청크 단위
- **최하위 조건별**로 개별 청크 생성
- 상위 계층 정보는 `condition_path`로 보존
- 비고는 매핑된 상태로 포함

### 5.2 청크 텍스트 형식

```
[소비자분쟁해결기준]
품목: {industry}
분쟁상황: {dispute_type}
조건: {condition_path}  ← "재파종 불가능 시 > 타품종으로 재파종이 가능한 경우"
해결방법: {resolution}
참고({keyword}): {note_content}  ← 키워드 매핑된 비고
참고: {note_content}  ← 위치 기반 매핑된 비고 (키워드 없음)
```

### 5.3 청크 예시

```
[청크 5]
[소비자분쟁해결기준]
품목: 종묘 등
분쟁상황: 파종 후 종자불량에 의한 발아불량 및 타품종 혼입
조건: 재파종 불가능 시 > 타품종으로 재파종이 가능한 경우
해결방법: 예상수익과 실수익과의 차액 배상
참고(예상수익): 예상수익은 당초 재배품목의 최근 3년간 평균수확량에 해당연도 농가 수취가격을 곱한 금액으로 산출함
참고(발아 불량): 발아 불량은 종자 포장에 표시된 발아율 이하로서 정상 발아기간 경과 후 15일 이내에 이의를 제기한 경우에 한함
```

### 7.2 PDF → 이미지 변환

```python
import fitz  # PyMuPDF
import base64

def pdf_to_images(pdf_path: str, dpi: int = 200) -> list:
    """PDF의 각 페이지를 base64 이미지로 변환"""
    doc = fitz.open(pdf_path)
    images = []
    
    for page_num in range(len(doc)):
        page = doc[page_num]
        pix = page.get_pixmap(dpi=dpi)
        img_bytes = pix.tobytes("png")
        base64_data = base64.b64encode(img_bytes).decode("utf-8")
        images.append({
            "page": page_num + 1,
            "data": base64_data
        })
    
    doc.close()
    return images
```

### 7.3 RAG 청크 변환 함수

```python
def flatten_to_chunks(data: dict) -> list:
    """계층 구조 → RAG용 플랫 청크"""
    chunks = []
    industry = data.get("industry", "")
    
    for item in data.get("items", []):
        dispute_type = item.get("dispute_type", "")
        item_notes = item.get("notes", [])
        
        for cond in item.get("conditions", []):
            condition = cond.get("condition", "")
            resolution = cond.get("resolution")
            cond_notes = cond.get("notes", []) + item_notes
            sub_conditions = cond.get("sub_conditions", [])
            
            if sub_conditions:
                for sub in sub_conditions:
                    sub_notes = sub.get("notes", []) + cond_notes
                    chunks.append(create_chunk(
                        industry=industry,
                        dispute_type=dispute_type,
                        condition_path=f"{condition} > {sub.get('condition', '')}",
                        resolution=sub.get("resolution"),
                        notes=sub_notes
                    ))
            else:
                chunks.append(create_chunk(
                    industry=industry,
                    dispute_type=dispute_type,
                    condition_path=condition,
                    resolution=resolution,
                    notes=cond_notes
                ))
    
    return chunks


def create_chunk(industry, dispute_type, condition_path, resolution, notes):
    """단일 청크 생성"""
    text_parts = [
        "[소비자분쟁해결기준]",
        f"품목: {industry}",
        f"분쟁상황: {dispute_type}"
    ]
    
    if condition_path:
        text_parts.append(f"조건: {condition_path}")
    
    if resolution:
        text_parts.append(f"해결방법: {resolution}")
    
    for note in notes:
        keyword = note.get("keyword")
        content = note.get("content", "")
        if keyword:
            text_parts.append(f"참고({keyword}): {content}")
        else:
            text_parts.append(f"참고: {content}")
    
    return {
        "text": "\n".join(text_parts),
        "metadata": {
            "industry": industry,
            "dispute_type": dispute_type,
            "condition_path": condition_path,
            "resolution": resolution,
            "notes": notes
        }
    }
```

```cypher
(Industry)-[:HAS_DISPUTE]->(DisputeType)
(DisputeType)-[:HAS_CONDITION]->(Condition)
(Condition)-[:HAS_SUB_CONDITION]->(SubCondition)
(SubCondition)-[:RESOLVED_BY]->(Resolution)
(SubCondition)-[:HAS_NOTE]->(Note)
```
