| 소관부처 | 공정거래위원회 |
| 문단 수 | 393개 |

### 계층 구조

```
Ⅰ. 대분류 (분류, 제목)
└─ 1. 중분류 (번호, 제목)
    └─ 가. 소분류 (번호, 제목)
        ├─ - 항목 (항목)
        ├─ <예시> (구분)

        ├─ ⇒ 설명 (설명)
        └─ 1) 세부항목 (번호, 내용, 세부)
            ├─ <예시> (구분)
            ├─ 본문 (본문)
            └─ ⇒ 설명 (설명)
```

### JSON 키 구조

| 레벨 | 패턴 | JSON 키 |
|------|------|---------|
| 대분류 | Ⅰ. Ⅱ. Ⅲ. | `분류`, `제목`, `내용` |
| 중분류 | 1. 2. 3. | `번호`, `제목`, `내용` |
| 소분류 | 가. 나. 다. | `번호`, `제목`, `내용` |
| 세부항목 | 1) 2) 3) | `번호`, `내용`, `세부` |
| 하이픈 | - 내용 | `항목` |
| 구분 | <예시> | `구분`, `내용` |
| 화살표 | ⇒ 내용 | `설명` |
| 일반 | 텍스트 | `본문` |

### JSON 예시

```json
{
  "분류": "Ⅱ",
  "제목": "일반사항",
  "내용": [
    {

      "제목": "개념정의 (할부거래법 제2조)",
      "내용": [

            { "항목": "\"선불식 할부거래\"란..." },
```

### 계층 구조

```
본문
├─ 제1조 (목적)
│   └─ 본문
├─ 제2조 (피해구제청구)
│   └─ 본문
├─ 제3조 (품목 및 보상기준)
│   └─ 본문
└─ 제4조 (재검토기한)
    └─ 본문

별표 (메타데이터)
├─ [별표 1] 대상품목 (ID: 3110555)
├─ [별표 2] 품목별 해결기준 (ID: 3110557)
├─ [별표 3] 품목별 품질보증기간 및 부품보유기간 (ID: 3110559)
└─ [별표 4] 품목별 내용연수표 (ID: 3110561)
```

### JSON 키 구조

| 레벨 | 패턴 | JSON 키 |
|------|------|---------|
| 조 | 제N조(제목) | `조`, `제목`, `내용` |
| 내용 | 텍스트 | `본문` |
| 별표 | [별표 N] | `제목`, `ID` |

### JSON 예시

```json
{
  "법령명": "소비자분쟁해결기준",
  "시행일": "2025-12-18",
  "소관부처": "공정거래위원회",
  "본문": [
    {
      "조": "제1조",
      "제목": "목적",
      "내용": [
        { "본문": "이 고시는 「소비자기본법」 제16조 제2항과..." }
      ]
    }
  ],
  "별표": [
    { "제목": "[별표 1] 대상품목", "ID": "3110555" },
    { "제목": "[별표 2] 품목별 해결기준", "ID": "3110557" }
  ]
}
```

### 특이사항

- 본문과 별표 2개의 최상위 구조로 구성
- 제1조~제4조의 단순한 조문 구조
- 별표는 iframe으로 로드되어 메타데이터(제목, ID)만 저장

- Ⅰ~Ⅳ 4개 대분류 사용 (Ⅰ, Ⅱ는 본문만, Ⅲ, Ⅳ는 하위 구조 포함)
- 세부항목에 괄호숫자 (1)(2)(3) 사용
- ㅇ 기호로 예시 항목 표시
- ※ 참고 표시 (이 지침만의 특징)

## 공통 JSON 최상위 구조

모든 행정규칙은 다음 최상위 키를 공통으로 갖습니다:

```json
{
  "법령명": "행정규칙명",
  "시행일": "YYYY-MM-DD",
  "법령번호": "예규 번호 또는 빈 문자열",
  "소관부처": "소관 부처명",
  "본문": [...],
  "별표": [...]  // 소비자분쟁해결기준만 해당
}
```
