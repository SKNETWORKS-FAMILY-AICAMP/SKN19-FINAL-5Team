## 🎯 현재 상황 분석

### 현재 적용 중인 방식

**Strategy 2: Flat Multi-Chunk + Re-ranking**

```
사례: "노트북 환불 분쟁" (총 1,500자)

DB 저장:
├─ [청크 1] 개요 + 주장 일부 (750자) - chunk_id: case_123_0
└─ [청크 2] 주장 나머지 + 판단 + 결론 (750자) - chunk_id: case_123_1

검색 결과:
1. 청크 2 (score: 0.92) ← "판단" 키워드 매칭
2. 청크 1 (score: 0.85) ← "개요" 키워드 매칭

Re-ranking:
→ 같은 URL(case_123)의 청크들을 그룹화
→ 청크 1, 2를 병합하여 전체 컨텍스트 제공
→ LLM에 전달: "[청크 1]\n\n---\n\n[청크 2]"
```

**장점**:
- ✅ 검색 정확도 양호 (평균 chunk size: ~700자)
- ✅ Re-ranking으로 완전한 컨텍스트 제공
- ✅ 제목 가중치 시스템으로 정확도 향상
- ✅ 이미 구현 완료, 바로 사용 가능

**한계**:
- ⚠️ Re-ranking 로직 의존 (API 레벨 처리)
- ⚠️ 청크 병합 시 구조 정보 손실 (어느 부분이 개요/판단인지 불명확)
- ⚠️ 긴 사례(2000자+)는 여전히 노이즈 포함 가능

## 🎯 최적 해결 방안: Hierarchical Chunking

### 개념

```
Parent Chunk (큰 청크, 컨텍스트용)
├─ Child Chunk 1 (작은 청크, 검색용)
├─ Child Chunk 2 (작은 청크, 검색용)
└─ Child Chunk 3 (작은 청크, 검색용)

전략:
1. Child로 검색 → 정확한 매칭
2. Parent를 LLM에 전달 → 완전한 컨텍스트
```

### 장점

1. **검색 정확도 최대화**
   - Child 청크가 작아서 정확한 매칭
   - 노이즈 최소화

2. **컨텍스트 완전성 보장**
   - Parent 청크에 전체 사례 저장
   - Re-ranking 불필요 (DB 레벨에서 해결)

3. **LLM 토큰 비용 절감**
   - 관련 없는 부분 제외
   - 정확한 컨텍스트만 전달

4. **구조 정보 유지**
   - Child 청크에 section_index 저장
   - "이것은 판단 부분입니다" 명시 가능

```python
def create_hierarchical_chunks(case_data: dict) -> dict:
    """
    하나의 사례를 Parent-Child 구조로 변환

    Args:
        case_data: {
            'id': 'case_123',
            'text': '전체 사례 내용...',
            'metadata': {...}
        }

    Returns:
        {
            'parent': {...},
            'children': [{...}, {...}, ...]
        }
    """
    full_text = case_data['text']  # 전체 사례
    case_id = case_data['id']
    metadata = case_data['metadata']

    # ===================================
    # Parent Chunk 생성 (전체 사례)
    # ===================================
    parent_chunk = {
        "chunk_id": f"{case_id}_parent",
        "dataset_type": "case",
        "chunk_hierarchy": "parent",  # 새 필드
        "chunk_type": "case_parent",
        "text": full_text,  # 전체 내용
        "embedding": create_embedding(full_text),
        "category": metadata.get("category"),
        "source_url": metadata.get("url"),
        "source_file": metadata.get("source_file"),
        "printed_page": metadata.get("printed_page"),
        "source_year": metadata.get("year"),
        "metadata": {
            **metadata,
            "is_parent": True,
            "child_count": 0,  # 나중에 업데이트
            "title": metadata.get("title")
        }
    }

    # ===================================
    # Child Chunks 생성 (의미 단위 분할)
    # ===================================
    child_chunks = []

    # 전략 1: 구조 기반 분할 시도
    sections = structure_based_split(full_text)

    if not sections:
        # 전략 2: 구조 불명확 시 semantic 분할
        sections = semantic_split(
            full_text,
            max_size=400,
            overlap=50
        )

    for i, section in enumerate(sections):
        child_chunk = {
            "chunk_id": f"{case_id}_child_{i}",
            "dataset_type": "case",
            "chunk_hierarchy": "child",  # 새 필드
            "chunk_type": "case_child",
            "text": section['text'],
            "embedding": create_embedding(section['text']),
            "category": metadata.get("category"),
            "source_url": metadata.get("url"),
            "source_file": metadata.get("source_file"),
            "printed_page": metadata.get("printed_page"),
            "source_year": metadata.get("year"),
            "parent_chunk_id": f"{case_id}_parent",  # 새 필드
            "child_order": i,  # 새 필드
            "metadata": {
                **metadata,
                "is_parent": False,
                "parent_id": f"{case_id}_parent",
                "section_index": i,
                "section_type": section.get('type', 'content'),  # 개요/주장/판단/결론
                "title": metadata.get("title")
            }
        }
        child_chunks.append(child_chunk)

    # Parent의 child_count 업데이트
    parent_chunk['metadata']['child_count'] = len(child_chunks)

    return {
        "parent": parent_chunk,
        "children": child_chunks
    }


def structure_based_split(text: str) -> list:
    """
    사례 구조 인식 후 분할

    인식 대상:
    - "1. 개요" / "개요:"
    - "2. 신청인 주장" / "질문:"
    - "3. 피신청인 주장"
    - "4. 판단" / "답변:"
    - "5. 결론"
    """
    import re

    patterns = [
        (r'^\d+\.\s*개요', 'overview'),
        (r'^\d+\.\s*(신청인|소비자)\s*주장', 'consumer_claim'),
        (r'^\d+\.\s*(피신청인|사업자)\s*주장', 'business_claim'),
        (r'^\d+\.\s*판단', 'judgment'),
        (r'^\d+\.\s*결론', 'conclusion'),
        (r'^질문\s*:', 'question'),
        (r'^답변\s*:', 'answer'),
    ]

    sections = []
    current_pos = 0

    # 패턴 매칭으로 구간 찾기
    matches = []
    for pattern, section_type in patterns:
        for match in re.finditer(pattern, text, re.MULTILINE | re.IGNORECASE):
            matches.append({
                'start': match.start(),
                'end': match.end(),
                'type': section_type
            })

    if not matches:
        return []  # 구조 불명확

    # 위치 순으로 정렬
    matches.sort(key=lambda x: x['start'])

    # 구간별로 텍스트 추출
    for i, match in enumerate(matches):
        start = match['start']
        end = matches[i + 1]['start'] if i + 1 < len(matches) else len(text)

        section_text = text[start:end].strip()

        if len(section_text) > 50:  # 너무 짧은 구간 제외
            sections.append({
                'text': section_text,
                'type': match['type']
            })

    return sections


def semantic_split(text: str, max_size: int = 400, overlap: int = 50) -> list:
    """
    의미 기반 청킹 (구조 불명확 시)

    Args:
        text: 전체 텍스트
        max_size: 최대 청크 크기 (문자)
        overlap: 청크 간 겹침 (문자)

    Returns:
        list of {'text': ..., 'type': 'content'}
    """
    from langchain.text_splitter import RecursiveCharacterTextSplitter

    splitter = RecursiveCharacterTextSplitter(
        chunk_size=max_size,
        chunk_overlap=overlap,
        separators=["\n\n", "\n", ". ", " ", ""],
        keep_separator=True
    )

    chunks = splitter.split_text(text)

    return [{'text': chunk, 'type': 'content'} for chunk in chunks]
```

```sql
-- 컬럼 추가
ALTER TABLE vector_chunks
ADD COLUMN IF NOT EXISTS chunk_hierarchy VARCHAR(20)
    CHECK (chunk_hierarchy IN ('parent', 'child', 'standalone')),
ADD COLUMN IF NOT EXISTS parent_chunk_id VARCHAR(500),
ADD COLUMN IF NOT EXISTS child_order INTEGER;

-- 인덱스 추가
CREATE INDEX IF NOT EXISTS idx_chunk_hierarchy
ON vector_chunks(chunk_hierarchy);

CREATE INDEX IF NOT EXISTS idx_parent_lookup
ON vector_chunks(parent_chunk_id)
WHERE parent_chunk_id IS NOT NULL;

CREATE INDEX IF NOT EXISTS idx_hierarchy_dataset
ON vector_chunks(dataset_type, chunk_hierarchy)
WHERE chunk_hierarchy IS NOT NULL;

-- Parent 청크 조회 함수
CREATE OR REPLACE FUNCTION get_parent_chunk(child_id VARCHAR)
RETURNS TABLE (
    chunk_id VARCHAR(500),
    text TEXT,
    category VARCHAR(50),
    source_url VARCHAR(1000),
    source_year INTEGER,
    metadata JSONB
) AS $$
BEGIN
    RETURN QUERY
    SELECT
        parent.chunk_id,
        parent.text,
        parent.category,
        parent.source_url,
        parent.source_year,
        parent.metadata
    FROM vector_chunks child
    JOIN vector_chunks parent ON child.parent_chunk_id = parent.chunk_id
    WHERE child.chunk_id = child_id
      AND parent.chunk_hierarchy = 'parent';
END;
$$ LANGUAGE plpgsql;

-- Child 청크들 조회 함수
CREATE OR REPLACE FUNCTION get_child_chunks(parent_id VARCHAR)
RETURNS TABLE (
    chunk_id VARCHAR(500),
    text TEXT,
    child_order INTEGER,
    metadata JSONB
) AS $$
BEGIN
    RETURN QUERY
    SELECT
        child.chunk_id,
        child.text,
        child.child_order,
        child.metadata
    FROM vector_chunks child
    WHERE child.parent_chunk_id = parent_id
      AND child.chunk_hierarchy = 'child'
    ORDER BY child.child_order;
END;
$$ LANGUAGE plpgsql;

-- 검색 함수 수정 (Child만 검색)
CREATE OR REPLACE FUNCTION search_hybrid_rrf_hierarchical(
    query_text TEXT,
    query_embedding VECTOR(1536),
    filter_dataset VARCHAR(20) DEFAULT NULL,
    filter_category VARCHAR(50) DEFAULT NULL,
    filter_year INT DEFAULT NULL,
    result_limit INT DEFAULT 10,
    rrf_k INT DEFAULT 60
)
RETURNS TABLE (
    parent_chunk_id VARCHAR(500),
    parent_text TEXT,
    rrf_score DOUBLE PRECISION,
    matched_child_id VARCHAR(500),
    matched_child_text TEXT,
    category VARCHAR(50),
    source_url VARCHAR(1000),
    source_year INTEGER,
    metadata JSONB
) AS $$
BEGIN
    RETURN QUERY
    WITH child_search AS (
        -- Child 청크만 검색
        SELECT * FROM search_hybrid_rrf(
            query_text,
            query_embedding,
            filter_dataset,
            filter_category,
            NULL,  -- document_type (case는 NULL)
            filter_year,
            result_limit * 3,  -- 넉넉하게
            rrf_k
        )
        WHERE chunk_hierarchy = 'child'  -- Child만
    ),
    parent_groups AS (
        -- Parent별로 그룹화
        SELECT
            cs.parent_chunk_id,
            MAX(cs.rrf_score) as max_score,
            array_agg(cs.chunk_id ORDER BY cs.rrf_score DESC) as child_ids,
            array_agg(cs.text ORDER BY cs.rrf_score DESC) as child_texts
        FROM child_search cs
        GROUP BY cs.parent_chunk_id
    )
    SELECT
        pg.parent_chunk_id,
        p.text as parent_text,
        pg.max_score as rrf_score,
        pg.child_ids[1] as matched_child_id,
        pg.child_texts[1] as matched_child_text,
        p.category,
        p.source_url,
        p.source_year,
        p.metadata
    FROM parent_groups pg
    JOIN vector_chunks p ON pg.parent_chunk_id = p.chunk_id
    WHERE p.chunk_hierarchy = 'parent'
    ORDER BY pg.max_score DESC
    LIMIT result_limit;
END;
$$ LANGUAGE plpgsql;
```

```python
# DB/03_01_search_api.py

def search_hierarchical(
    conn,
    query_text: str,
    query_embedding: List[float],
    dataset_filter: Optional[str],
    category_filter: Optional[str],
    year_filter: Optional[int],
    top_k: int
) -> List[dict]:
    """
    Hierarchical 검색

    1. Child 청크로 검색 (정확도 높음)
    2. Parent 청크를 컨텍스트로 반환 (완전성 보장)
    """
    cursor = conn.cursor()

    # Child 청크만 검색
    cursor.execute("""
        SELECT
            chunk_id,
            parent_chunk_id,
            text,
            1 - (embedding <=> %s::vector(1536)) AS similarity
        FROM vector_chunks
        WHERE
            chunk_hierarchy = 'child'  -- Child만
            AND (%(dataset)s IS NULL OR dataset_type = %(dataset)s)
            AND (%(category)s IS NULL OR category = %(category)s)
            AND (%(year)s IS NULL OR source_year = %(year)s)
        ORDER BY embedding <=> %s::vector(1536)
        LIMIT %(limit)s
    """, {
        'dataset': dataset_filter,
        'category': category_filter,
        'year': year_filter,
        'limit': top_k * 3  # 넉넉하게
    })

    child_results = cursor.fetchall()

    # Parent별로 그룹화
    parent_groups = {}
    for child in child_results:
        parent_id = child['parent_chunk_id']
        if parent_id not in parent_groups:
            parent_groups[parent_id] = {
                'parent_id': parent_id,
                'children': [],
                'max_score': 0
            }
        parent_groups[parent_id]['children'].append(child)
        parent_groups[parent_id]['max_score'] = max(
            parent_groups[parent_id]['max_score'],
            child['similarity']
        )

    # 각 그룹의 Parent 청크 가져오기
    results = []
    for parent_id, group in parent_groups.items():
        cursor.execute("""
            SELECT
                chunk_id,
                text,
                category,
                source_url,
                source_year,
                metadata
            FROM vector_chunks
            WHERE chunk_id = %s AND chunk_hierarchy = 'parent'
        """, (parent_id,))

        parent = cursor.fetchone()
        if parent:
            results.append({
                'chunk_id': parent['chunk_id'],
                'text': parent['text'],  # 전체 사례
                'score': group['max_score'],
                'category': parent['category'],
                'source_url': parent['source_url'],
                'source_year': parent['source_year'],
                'metadata': {
                    **parent['metadata'],
                    'matched_children': [c['chunk_id'] for c in group['children']],
                    'matched_child_preview': group['children'][0]['text'][:100]
                }
            })

    # 점수 기준 정렬
    results.sort(key=lambda x: x['score'], reverse=True)

    cursor.close()
    return results[:top_k]


# API 엔드포인트에 추가
```

```python
    # Parent Chunk (컨텍스트용)
    "parent": {
        "min": 1000,   # 최소 1,000자 (컨텍스트 확보)
        "max": 3000,   # 최대 3,000자 (너무 길면 노이즈)
        "target": 1500 # 목표 1,500자
    },

    # Child Chunk (검색용)
    "child": {
        "min": 200,    # 최소 200자 (의미 유지)
        "max": 500,    # 최대 500자 (정확한 매칭)
        "target": 350, # 목표 350자
        "overlap": 50  # 청크 간 50자 겹침 (문맥 유지)
    },

    # 분할 기준
    "split_threshold": 400,  # 400자 이하면 Parent만 생성
    "max_children": 8        # 최대 Child 수 제한
}
```

### 청킹 전략 흐름도

```
사례 입력 (text + metadata)
    ↓
[전체 길이 확인]
    ↓
    ├─ ≤ 400자
    │   └→ Parent만 생성 (hierarchy: 'standalone')
    │
    ├─ 400~1000자
    │   └→ Parent + Child 2~3개
    │       ├─ 구조 인식 시도
    │       └─ 실패 시 semantic 분할
    │
    └─ > 1000자
        └→ Parent + Child 3~8개
            ├─ 구조 인식 우선 (개요/주장/판단)
            └─ 실패 시 semantic 분할
```

### 구현 예시

```python
def smart_chunking(text: str, metadata: dict) -> dict:
    """
    사례 특성에 맞는 지능형 청킹

    Returns:
        {
            'strategy': 'standalone' | 'hierarchical',
            'parent': {...},
            'children': [...]
        }
    """
    total_length = len(text)
    case_id = metadata.get('id', 'unknown')

    # ========================================
    # Case 1: 짧은 사례 (≤ 400자)
    # ========================================
    if total_length <= HIERARCHICAL_CHUNK_CONFIG['split_threshold']:
        return {
            'strategy': 'standalone',
            'parent': {
                'chunk_id': f"{case_id}_standalone",
                'chunk_hierarchy': 'standalone',
                'text': text,
                'embedding': create_embedding(text),
                'metadata': {**metadata, 'is_parent': True, 'child_count': 0}
            },
            'children': []
        }

    # ========================================
    # Case 2: 중간/긴 사례 (> 400자)
    # ========================================

    # 전략 1: 구조 기반 분할 시도
    sections = structure_based_split(text)

    if not sections:
        # 전략 2: 구조 불명확 시 semantic 분할
        sections = semantic_split(
            text,
            max_size=HIERARCHICAL_CHUNK_CONFIG['child']['max'],
            overlap=HIERARCHICAL_CHUNK_CONFIG['child']['overlap']
        )

    # Child 수 제한
    if len(sections) > HIERARCHICAL_CHUNK_CONFIG['max_children']:
        # 너무 많으면 병합
        sections = merge_small_sections(
            sections,
            target_count=HIERARCHICAL_CHUNK_CONFIG['max_children']
        )

    # Parent-Child 생성
    return create_hierarchical_chunks({
        'id': case_id,
        'text': text,
        'metadata': metadata
    })
```
