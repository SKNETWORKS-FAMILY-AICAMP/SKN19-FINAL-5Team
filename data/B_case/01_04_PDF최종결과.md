## 5. 데이터 특징

### 5.1 해결사례

- **PDF_1**: 카테고리(items) → 사례(cases) → 세부정보(sections) 계층적 구조
- **PDF_2**: 단순 리스트 형태, 각 사례가 독립적인 필드 보유

### 5.2 조정사례

- **PDF_1**: 당사자 주장은 null, 판단과 페이지 정보만 중첩
- **PDF_2**: 당사자 주장을 applicant/respondent로 분류, 상세한 파싱 메타정보

### 6.1 키값 정규화

```

  title → case_title (또는 그대로)
  sections.사건개요 → case_overview
  sections.쟁점사항 → case_issues

  judgement.reason → decision_reason
  judgement.order → decision_order
  claims.applicant → applicant_claims
  claims.respondent → respondent_claims
```
