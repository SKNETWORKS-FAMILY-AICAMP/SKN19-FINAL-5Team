## 🔧 파싱 전략 비교

### 1. 구형식 파싱 (2010~2020)

**파싱 도구**: `01_01_parsing_solution_1.py`

#### 기술 스택
- **라이브러리**: pdfplumber
- **방법**: 텍스트 기반 PDF 파싱
- **특징**:
  - `layout=True` 옵션으로 레이아웃 보존
  - 정규식 패턴 매칭으로 섹션 구분
  - 텍스트 추출 후 후처리

#### 파싱 프로세스
```python
1. PDF 페이지별 텍스트 추출 (layout=True)
2. 정규식으로 케이스 번호/제목 감지
3. "신청내용", "처리내용", "처리결과" 섹션 분리
4. 텍스트 정리 및 구조화
```

#### JSON 구조
```json
{
  "source_pdf": "파일명.pdf",
  "year": "2010",
  "items": [
    {
      "case_number": "숫자",
      "title": "제목",
      "content": {
        "신청내용": "내용",
        "처리내용": "내용",
        "처리결과": "내용"
      }
    }
  ]
}
```

#### 장점
- ✅ 빠른 처리 속도
- ✅ 비용 무료 (로컬 처리)
- ✅ 안정적인 텍스트 추출

#### 단점
- ❌ Bullet point (●, ○, -) 일부 누락
- ❌ 복잡한 표 구조 인식 어려움
- ❌ 레이아웃이 복잡한 경우 정확도 저하

### 2. 신형식 파싱 (2022~2024)

**파싱 도구**:
- `01_01_parsing_solution_2_1.py` (메인 파싱)
- `01_01_parsing_solution_2_2.py` (후처리)

#### 기술 스택
- **메인 파싱**: Gemini 2.0 Flash Vision API
- **모델**: `gemini-2.0-flash-exp`
- **방법**: 이미지 기반 Vision AI 파싱
- **특징**:
  - PDF 페이지를 이미지로 변환 (200 DPI)
  - Few-shot 프롬프트 엔지니어링
  - 표 구조 이해 및 셀 구분
  - 후처리 스크립트로 오류 자동 수정

#### 파싱 프로세스
```python
1. PDF 페이지 → 이미지 변환 (PyMuPDF)
2. Gemini Vision API 호출 (Few-shot 프롬프트)
3. JSON 응답 파싱 및 검증
4. 후처리 스크립트 실행:
   - 섹션 구분 오류 수정
   - 표 외부 텍스트 제거
   - 특정 케이스 수동 수정 (케이스 6, 13)
```

#### Few-shot 프롬프트 구조
```
1. 표 구조 예시 제공 (2열 테이블)
2. Bullet point 유지 강조 (●, ㅇ, ○, -)
3. 섹션 구분 명확화 (왼쪽 열 헤더 기준)
4. 표 외부 텍스트 무시 지시
5. JSON 출력 형식 명시
```

#### JSON 구조
```json
{
  "연도": "2022",
  "파일명": "2022년 우수 소비자분쟁 해결사례 22선.pdf",
  "사례": [
    {
      "번호": 1,
      "제목": "(카테고리) 제목",
      "신청 내용": "내용",
      "처리 과정": "내용",
      "처리 결과": "내용"
    }
  ]
}
```

#### 장점
- ✅ **매우 높은 정확도** (표 구조 완벽 인식)
- ✅ **Bullet point 완벽 보존** (●, ㅇ, ○, -)
- ✅ **복잡한 레이아웃 처리 가능**
- ✅ **2열 표 구조 정확히 구분**
- ✅ Few-shot 학습으로 일관성 향상

#### 단점
- ❌ 느린 처리 속도 (페이지당 1~2초)
- ❌ API 비용 발생
- ❌ Rate limit 제약 (429 에러 발생 가능)
- ❌ 일부 케이스는 후처리 필요

#### 후처리 내용
```python
# 01_01_parsing_solution_2_2.py
1. 섹션 구분 오류 감지 및 수정
   - "신청 내용"에 섞인 "처리 과정" 내용 분리

2. 표 외부 텍스트 처리
   - 페이지 하단의 별도 텍스트를 [대괄호]로 표시

3. 특정 케이스 수동 수정
   - 2022년 케이스 6: 누락된 bullet point 복원
   - 2024년 케이스 13: 섹션 구분 수정
```

## 📋 파싱 결과 차이점

### 구조적 차이

| 항목 | 구형식 (2010~2020) | 신형식 (2022~2024) |
|------|-------------------|-------------------|
| **키 네이밍** | 영어 (source_pdf, year, items) | 한글 (연도, 파일명, 사례) |
| **케이스 키** | case_number, title, content | 번호, 제목, 신청 내용, 처리 과정, 처리 결과 |
| **내용 구조** | content 객체 안에 중첩 | 최상위 레벨에 평탄화 |
| **섹션명** | 신청내용, 처리내용, 처리결과 | 신청 내용, 처리 과정, 처리 결과 |

### 내용 품질 차이

| 항목 | 구형식 | 신형식 |
|------|--------|--------|
| **Bullet point 보존** | 일부 누락 (●, ○ 불완전) | 완벽 보존 (●, ㅇ, ○, -, ①②③...) |
| **표 셀 구분** | 불완전 (셀 경계 인식 오류) | 완벽 (2열 구조 정확히 인식) |
| **레이아웃 보존** | 기본적 (줄바꿈 유지) | 고급 (들여쓰기, 기호 모두 유지) |
| **섹션 구분** | 정규식 기반 (오류 가능) | Vision AI + 후처리 (높은 정확도) |
| **특수 기호** | 일부 손실 | 완전 보존 ([대괄호], 숫자기호 등) |
